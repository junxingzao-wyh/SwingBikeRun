## 一、最重要的项目修改原则

必须严格遵守以下要求：

1. 保留现有参数化赛道（弧长 s 从 0 到 1340，u 横向偏移），不得推翻赛道数学模型。
2. 保留五段状态机 swim → t1 → bike → t2 → run 及其边界常量 SWIM_END=300 / T1_END=330 / BIKE_END=950 / T2_END=980 / FINISH_S=1300。
3. 保留换项区「到点后按空格确认换装」的核心玩法和分阶段 Kit 换装逻辑。
4. 保留标志门判定、障碍碰撞、补给拾取、弯道抓地、体力系统、连击得分、冲刺/刹车双输入。
5. 不得为了追求视觉效果而随意删除原有游戏机制。
6. 不得擅自改变赛道拓扑、赛段边界、碰撞盒坐标关系。
7. 优先通过材质、灯光、后期、动画和空间层次提升效果，而非重写赛道几何。
8. 不要只输出修改建议，必须尽可能实际修改项目代码。
9. 不要只生成静态效果图，要保证项目仍然可以运行和交互。
10. 修改前先检查现有代码结构、配置常量和依赖关系，避免破坏原有功能。

如果某项修改需要改变原有模型或结构，先寻找不破坏参数化赛道的替代实现方式。

## 二、整体视觉定位

**项目名称：LAKELINE 湖线铁三**

**最终视觉风格：Cinematic Outdoor Sports Editorial · 电影感户外体育编辑风**

视觉关键词：Cinematic、Athletic、Natural、Atmospheric、Premium、Authentic、Varied、Cohesive

不要做成普通低质量卡通游戏，也不要强行改成超写实风格。

保留现有模型的低多边形和几何化特征，通过更高级的灯光、材质、色彩变化、空间层次和后期处理，让现有模型呈现出精致的体育赛事宣传片级视觉效果。

- 所有赛段使用相同颜色（当前问题：水、路、地形之间色彩差异不够明确）

- 所有拱门/立柱形状完全相同
- 水面只有水平条纹没有涟漪或高光变化
- 森林树全是同一种绿色同一种形状
- 过强的 Bloom 导致拱门横幅文字模糊
- 所有物体阴影一样深、一样硬

整体应当具有明确的赛段差异化色彩、远近空气透视、冷暖光比和视觉引导线。

## 三、第一阶段：分赛段视觉升级

### 1. 游泳段（s 0 → 300）

当前问题：
- 水面只有水平条纹，缺少真实水波的斜向推进感
- 泳道浮标线太细，远距离辨识度不足
- 起点浮台和游泳者剪影太扁平
- 两岸山体缺少层次感

优化要求：
- 水面使用三到四层不同频率的叠加波纹 shader，加入斜向推进和高光条带
- 近岸（s 270 → 300）水色变浅，增加沙底可见的透明度渐变
- 泳道浮标加粗，加入微摇摆动画（频率随距离衰减）
- 起点浮台增加防滑纹理边缘和固定绳索
- 游泳者剪影增加更明显的划水前后摆动和入水水花粒子
- 两岸山体：近岸草坡 + 远岸松林 + 最远处低山剪影三层

### 2. T1 换项区（s 300 → 330）

当前问题：
- 换项区地面颜色和周围草地区分不够明确
- 换项架摆放单调
- 拱门横幅缺少明显的 T1 标识和箭头引导

优化要求：
- 换项区地面改为奶油沙色，边缘用浅灰色铺路石过渡
- 换项架上增加视觉化的挂衣钩、头盔、跑鞋等配件（作为 InstancedMesh 装饰）
- 拱门横幅增大，T1 文字用白色加发光效果，下方加箭头指向骑行出口
- 增加两侧的自行车停放架和橙色锥桶引导

### 3. 骑行段（s 330 → 950）

当前问题：
- 沥青路缺少明显的车道线和路肩区分
- 发夹弯（s 540 附近）的视觉引导不足
- 路障和警示标志太小太远看不清
- 林间段（s 680 → 820）树的密度和色彩单一

优化要求：
- 路面增加白色虚线车道分隔线和实线边缘，路肩用稍浅灰色区别
- 发夹弯入口处增加三块橙色警示标志，路边放一排橙色反光锥
- 路面增加轻微的横向路面排水纹和补丁痕（不要太脏）
- 森林段树做高低错落：近树深绿高锥 + 远树浅绿小三角 + 地面灌丛点
- 下坡段（s 820 → 900）路两侧增加山体阴影条带增强纵深感
- 骑行者剪影增加更明显的坐姿/摇车两种姿态切换

### 4. T2 换项区（s 950 → 980）

当前问题：
- 和 T1 区分度不够（当前默认同色同材质）
- 缺少跑步鞋和 bib 号码布等换项视觉线索

优化要求：
- 地面用沙砾色（比 T1 的奶油沙更硬更冷）
- 换项架上挂跑鞋、号码布和腰带（视觉化装饰）
- 拱门横幅改成 T2 + RUN EXIT 双标识
- 出口地面改成红跑道材质，形成明显的视觉过渡

### 5. 跑步段（s 980 → 1300）

当前问题：
- 红跑道的质感单一
- 补给拱门（s 1012）和终点拱门（s 1300）辨识度可以更高
- 林荫带植物太单调

优化要求：
- 跑道增加白虚线分道线（每 4m 一段）和轻微的横向防滑纹
- 跑道两侧用绿色装饰条，内侧用灰色路缘石
- 补给站增加更明显的帐篷、桌子、水瓶堆和遮阳伞
- 林荫带树距更有节奏感：疏 → 密 → 疏形成视觉呼吸
- 终点拱门增加黑白格冲刺线（铺在路面上）、两侧彩旗和观众台（低多边形剪影）

## 四、第二阶段：专业灯光系统

目前场景的主要问题是所有赛段使用几乎一样的环境光，缺少赛段差异化的情绪氛围。

### 按赛段设置灯光基调

**游泳段：上午侧逆光，冷蓝调**
- 主光：DirectionalLight 角度偏高，色温 5500K，强度 1.0
- 补光：HemisphereLight 天空色 #87CEEB / 地面色 #E8E0D0，强度 0.45
- 水面反光：用 reflectivity 材质参数或简单的 cubemap 近似

**骑行段：午前阳光，暖金调**
- 主光：DirectionalLight 角度中等，色温 5200K，强度 1.1
- 补光：略偏暖的 HemisphereLight，强度 0.4
- 阴影：自行车投影路面要够深，帮助速度感

**跑步段：下午顺光，金绿调**
- 主光：DirectionalLight 角度偏低，色温 5000K，强度 1.05
- 补光：HemisphereLight 更暖，强度 0.42
- 终点处：增加微弱的点光源（低强度），让拱门横幅边缘有自发光感

### 技术要求
- 合理使用 HemisphereLight + DirectionalLight 作为基础组合
- 赛段切换时（recordSplit 触发处）平滑过渡主光颜色和强度（3–5 秒渐变）
- 阴影只在主光方向启用，控制在路面+主要建筑上
- 障碍物、路障等小物体投影可实时；大量树木投影考虑烘焙或关闭
- 避免为了气氛大量加 PointLight 导致性能下降

## 五、第三阶段：镜头与构图升级

### 1. 第三人称跟随镜头（玩家主观操控）

当前问题：
- 切换赛段时没有镜头过渡
- 换项区和拱门处相机容易穿过立柱
- 跑步段的林荫下视野偏暗

优化要求：
- 跟随相机按赛段设置不同的距离和高度：
  - 游泳：稍远稍低（俯视浮标线）
  - 骑行：稍近稍高（看前方弯道）
  - 跑步：中等距离（看脚下跑道）
- 相机平滑阻尼（已有基础，可加强）
- 相机碰撞检测：在拱门立柱和换项架附近自动抬高或侧移
- 赛段切换时 1–2 秒的柔和推拉过渡
- 拱门正下方时相机自动轻微后仰避免横幅遮挡顶部视线

### 2. 俯视全景镜头（封面页 / 结果页）

优化要求：
- 封面页：展示完整赛道三分之二，起点浮台在左下，终点拱门在右上
- 结果页：聚焦终点拱门和冲刺线区域
- 全景相机角度在 45–55° 之间，保持可读性

## 六、第四阶段：动态效果和氛围系统

### 1. 水面系统
- 多层叠加波纹 shader，带斜向推进方向
- 岸边处振幅加大，体现浅水区域
- 游泳者经过处产生局部扩散波纹（BufferGeometry + Sprite）

### 2. 树木环境动画
- 树叶轻微摆动（绕 Y 轴 sin 摇摆，频率 0.8–1.5Hz）
- 使用 InstancedMesh 的 instanceMatrix 做，避免每帧重建

### 3. 拱门飘带
- 拱门横幅边缘有轻微飘动动画（只在垂直方向 sin 变形，保持横幅文字可读）
- 终点拱门的黑白格冲刺线可增加极轻微的流动效果

### 4. 云影
- 用一张低分辨率动态纹理贴在一个大的地面投影平面上
- 云影缓慢移动，不与主光冲突
- 强度可调，关闭时直接隐藏

### 5. 水花 / 脚踏粒子
- 游泳划水：简单 Sprite 飞溅
- 骑行过积水：可选关闭（当前无积水，可后期加）
- 跑步冲刺：脚下少量尘土粒子（InstancedMesh）

所有动画使用统一的时间更新机制，正确处理 deltaTime。

## 八、第六阶段：Three.js 性能优化

必须考虑网页 3D 的实际运行。

重点优化：
1. 大量重复树木使用 InstancedMesh（当前已是，但可检查是否所有类型都覆盖）
2. 减少不必要的实时阴影（只在路面 + 主要建筑上）
3. 贴图分辨率：装饰性低重要性贴图降到 256，关键建筑保持 512
4. 水面 shader 计算量控制在 GLES300 可接受范围
5. 粒子系统使用 BufferGeometry，避免独立 Mesh
6. 视锥体剔除确保所有非相机视野物体被自动剔除
7. 正确释放临时资源（场景销毁、材质 dispose）
8. 减少每帧不必要的全局状态拷贝

目标：
桌面端稳定 55–60 FPS（Chrome 最新版）。
移动端（iPhone / Android 主流机型）自适应，优先保证 30 FPS 稳定运行。

不要为了视觉效果盲目增加后期特效，尤其注意 Bloom、大量动态 PointLight 和高分辨率 shadow map 对性能的影响。
